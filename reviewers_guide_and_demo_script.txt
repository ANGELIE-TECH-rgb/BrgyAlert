1. PROJECT FEATURES REVIEWER GUIDE
================================================================================
This guide details the core capabilities of the BrgyAlert ecosystem, highlighting
how it addresses disaster response challenges and local administration needs.

A. Citizen Client Features (Citizen Mobile Role)
* Touch-Optimized Reporting Wizard: A clean, multi-step interface featuring 
  quick-action categories (Fire, Flood, Medical, Crime, Accident, General) designed
  for fast input under stressful conditions.
* Real-Time GPS Geolocation Lock: Utilizes native Expo APIs to pin coordinates
  automatically, eliminating manual address typing.
* Local Photo Compression: Reduces raw device photo sizes (e.g., 5MB) down to 
  ~200KB before upload, conserving cellular bandwidth during congestion.
* Smart Offline SMS Fallback (Delimiter Protocol):
  - When connection is lost, it formats reports into compressed, delimiter-spaced
    strings (e.g., `BA!Cat!Landmark!Details`).
  - Pre-fills the device's native SMS editor addressed to up to 5 admin-configured 
    gateway numbers.
  - Automatically tags reports with a grey "OFFLINE (SMS)" badge and "#SMS-" serial prefix.
* Concurrency-Locked Background Sync: Automatically detects network recovery,
  synchronizing queued offline reports to Firestore while using mutex locks to
  prevent duplicate database writes.
* Active Report Status Timeline: Visual step tracker showing report progression:
  [Submitted ➔ Under Review ➔ Dispatched ➔ Resolved].
* Privacy Controls: Supports anonymous submissions to encourage reporting without 
  fear of exposure.
* Community Safety Directory: Direct lookup of active Evacuation Centers (with live 
  capacities) and direct-dial emergency hotlines.
* Two-Way Incident Chat: Dedicated text channels linked to each active report.

B. Administrative Portal Features (Admin/Responder Mobile Role)
* Live Priority Incident Queue: Displays incoming alerts dynamically sorted by AI-
  predicted urgency and keyword prioritization.
* Incident Triage Console: Full view of evidence, coordinates, and dispatcher 
  controls (Assigned Crew, Urgency, Category override).
* Deep Link Navigation: Instant linkage to external mapping apps (Google Maps / Apple 
  Maps) for route routing directly to incident coordinates.
* Field Evacuation Control: Enables center leads to update operational states 
  (Open, Full, Closed) and adjust live occupancy numbers.
* Broadcast Alert Composer: Sends system-wide alerts to citizen feeds and 
  outbound SMS alerts to the zone registry.
* Toggled Barangay Configuration Card: Protects critical system variables (gateways,
  hotlines, estimated response times) behind a confirmation lock.
* Real-Time Incident Chat Console: Two-way communication hub to direct on-site citizens.

C. AI-Powered Features (Gemini 2.5 Flash Engine)
* AI Incident Triage: Suggests the most fitting category and urgency level as the
  citizen types their description, offering a debounced "Tap to Apply" chip.
* Multimodal AI Validity Guard: Validates submitted reports for spam, keyboard mashing,
  or joke descriptions, and verifies if attached photos contextually match the 
  reported incident category (preventing prank uploads).
* Tagalog Active-Voice Summaries: Generates concise, 10-word summaries for admin cards,
  cached in Firestore to prevent duplicate API costs.
* Smart Reply Co-Pilot: Recommends 3 context-aware quick responses inside the chat screen.
* Sliding-Window Rate Limiting: Restricts requests (3/hr for citizens, 15/hr for admins)
  via AsyncStorage to protect API keys.

2. TECH STACK REVIEWER GUIDE
================================================================================
This section explains the architectural components, chosen technologies, and the 
rationale behind the serverless, hybrid-offline stack.

* Programming Language: JavaScript (ES6+)
  - Rationale: Unified programming language across the entire application ecosystem, including the React Native front-end client-side logic, mobile components, and Firebase serverless backend integrations (Node.js environments).

* Mobile Application Framework: React Native (Expo SDK 51+)
  - Rationale: Single, cross-platform codebase targeting Android and iOS, compiled
    with the Hermes JS engine for optimized memory execution on low-end devices.
  - Routing: React Navigation (Tab & Stack navigators) executing dynamic Role-Based 
    Access Control (RBAC).

* Serverless Infrastructure: Firebase Suite (Free-Tier Optimized)
  - Firebase Authentication: Manages secure user registries and issues JWT tokens.
  - Cloud Firestore: Serverless NoSQL Document database hosting real-time listener 
    subscriptions (for chat, alerts, and configurations).
  - Cloud Storage: Secure bucket hosting photo evidence.

* AI Engine: Google Gemini API (gemini-2.5-flash)
  - Rationale: Highly responsive, multimodal capability to process both text inputs 
    and base64 image data packages in a single API call with zero infrastructure overhead.

* SMS Gateway Integration: Semaphore.co SMS API
  - Rationale: High-deliverability API used to dispatch status updates, broadcast SMS
    alerts, and receive delimiter-parsed incoming SMS payloads.

* Local Persistence & Cache: AsyncStorage & Expo NetInfo
  - Rationale: Keeps offline reports, credentials, and configuration cache persistent 
    locally, monitoring network changes to trigger sync cycles.

4. SYSTEM ARCHITECTURE & INTEGRITY REVIEWER GUIDE
================================================================================
How BrgyAlert guarantees system security, scalability, and database integrity:

* Role-Based Access Control (RBAC):
  - Enforced via Firestore Rules and client-side route guards.
  - The `users` collection contains user profiles, with the `role` field ("citizen" or 
    "admin") strictly validated.
  - Administrative collections (e.g. `broadcasts`, `barangay_config`) only permit 
    writes if the authenticated user's profile role matches "admin".

* Orphan Notification Auto-Cleanup:
  - File: [notificationService.js](file:///c:/Users/Acer/OneDrive/Desktop/capstone/BrgyAlert/BrgyAlert_Mobile/src/services/notificationService.js)
  - Whenever an administrator declines or deletes a report, the database triggers a 
    cleanup function that automatically deletes notification documents referencing the 
    removed report ID, ensuring user badges and lists remain clean.

* Firestore Structural Integrity:
  - Incident documents contain nested coordinates, status timelines, and AI validation flags.
  - Offline SMS reports use a serial code structure starting with `#SMS-` to ensure 
    they are easily distinguishable from online entries before background ingestion occurs.

5. SECURITY REVIEWER GUIDE
================================================================================
This guide evaluates the multi-layered security framework protecting the 
BrgyAlert platform against common web and system vulnerabilities.

* Secure Client-Side Config UI:
  - Configuration settings (SMS gateway API keys, emergency phone contact lists, 
    hotlines, response targets) are read-only by default.
  - Changes are guarded by confirmation prompts and runtime cache reverts to prevent 
    unauthorized or accidental modifications.

* Client-Side Input Sanitization:
  - Incident description strings are sanitized to strip markdown, HTML/script injections, 
    and prompt bypass directives before they are forwarded to the Gemini AI models 
    or stored in Firestore documents.

* Firebase Firestore Rule Restrictions (firestore.rules):
  - authenticated: Restricts document reads and writes to authenticated accounts.
  - horizontal-privilege: Citizens are strictly locked out of viewing or editing other 
    citizens' emergency incidents or private profile fields.
  - privilege-escalation: Prevent users from updating their own account document 
    "role" field (cannot upgrade status from "citizen" to "admin").
  - write-protection: Restricts global tables (evacuation centers, hotlines, and 
    SMS gateway configurations) to authenticated Admin/Responder accounts.
  - delete-protection: The system blocks client-side deletion of alerts to preserve 
    historical incident dispatches and blotter integrity.

* Rate Limiting & API Key Safety:
  - Embedded keys are handled through environment configurations.
  - Sliding-window rate limiters block flood attempts locally, preventing server-side 
    resource exhaustion.

6. PERFORMANCE & BANDWIDTH OPTIMIZATION GUIDE
================================================================================
* Local Photo Compression Pipeline:
  - Raw smartphone cameras produce photos of 4MB to 12MB.
  - The local pipeline uses Expo Image Manipulator to resize and compress photos 
    down to ~200KB before uploading to Firebase Storage.
  - This saves over 95% of bandwidth, speeding up submission times by up to 10x 
    on slow/congested networks.

* local Persistence Caching:
  - Critical reference data (emergency hotlines, active evacuation shelters, and 
    barangay configuration profiles) are cached in local memory.
  - Reduces redundant Firestore reads, keeping network egress charges at 0.

* Optimized AI Token Delivery:
  - Input details are sanitized and truncated (max 800 characters) before sending 
    to Gemini to keep token counts low.
  - Prompts are structured to request raw JSON, preventing conversational fluff and 
    reducing output token counts.

7. FIRESTORE DATABASE SCHEMA & RELATIONSHIP MAPPING
================================================================================
* Users Collection (`/users/{userId}`):
  - `uid` (String): Unique authentication identifier.
  - `name` (String): First and last name of the user.
  - `email` (String): Register email.
  - `phone` (String): Contact number.
  - `role` (String): Access tier ("citizen", "responder", or "admin").
  - `createdAt` (Timestamp): Profile creation time.

* Alerts Collection (`/alerts/{alertId}`):
  - `userId` (String): Reference to the creator's user ID (or "guest" for offline).
  - `category` (String): Incident classification ("Fire", "Flood", etc.).
  - `description` (String): User's description text.
  - `location` (GeoPoint): Geolocation latitude and longitude.
  - `photoUrl` (String): Reference link to uploaded storage media.
  - `status` (String): Report progression status.
  - `urgency` (String): Urgency ranking.
  - `isAnonymous` (Boolean): Anonymous toggle.
  - `source` (String): Submission mechanism ("online_app" or "offline_sms").
  - `aiSummary` (String): 10-word Tagalog incident summary.
  - `aiFlaggedFake` (Boolean): Flag indicating suspicious content.
  - `aiFakeReason` (String): AI reasoning for validity flag.
  - `createdAt` (Timestamp): Date and time submitted.

* Incident Messages Collection (`/alerts/{alertId}/messages/{messageId}`):
  - `senderId` (String): User UID of message sender.
  - `senderName` (String): Display name.
  - `text` (String): Text message payload.
  - `createdAt` (Timestamp): Time sent.

* User Notifications Collection (`/users/{userId}/notifications/{notificationId}`):
  - `alertId` (String): Reference link to the source incident.
  - `title` (String): Notification header.
  - `body` (String): Detailed message.
  - `isRead` (Boolean): Read status tracker.
  - `createdAt` (Timestamp): Timestamp.

9. REVIEWER PANEL QUESTIONNAIRE & VERIFICATION CHECKLIST
================================================================================
Q1: How does the system prevent duplicate submissions during background sync when 
    a user's network keeps disconnecting and reconnecting?
A1: The background synchronization process is guarded by a mutable React ref 
    (`isSyncingRef`) that acts as a runtime lock. Once triggered, the lock is 
    immediately engaged, preventing concurrent sync cycles from firing. In addition, 
    the local offline queue in AsyncStorage is cleared immediately after a successful 
    Firestore write, ensuring data is written once.

Q2: Why use a delimited string payload for offline SMS fallback instead of sending 
    raw descriptive text?
A2: Delimited formats (such as `BA!Cat!Landmark!Details`) allow structured fields 
    (Category, Landmark, Details) to be compressed into a single 160-character SMS 
    message. This structure enables downstream SMS gateways (e.g. Semaphore.co) to 
    parse the payload and populate Firestore fields dynamically, keeping database 
    records clean.

Q3: How do you handle Gemini API key exposure in a client-side environment?
A3: The Gemini API key is loaded via build-time environment configurations 
    (`EXPO_PUBLIC_GEMINI_API_KEY`). To prevent abuse, requests are throttled 
    locally using a sliding-window rate limiter stored in AsyncStorage, limiting 
    citizens to 3 requests per hour.

Q4: How is database integrity managed when reports are deleted?
A4: The system executes an automated cleanup function (`notificationService.js`) 
    whenever a report is deleted, scanning and removing all notification records 
    referencing the deleted report ID to maintain data integrity.

   * Return to the "My Reports" feed.

5. Watch Auto-Sync in Action:
   * Point out that within seconds of network recovery, the background sync triggers.
   * The status badge updates from "OFFLINE" to "Submitted" (online status) and sync locks

   * Tap "Edit Config". Show how input text fields become active.
   * Change a gateway number, then tap "Cancel". Point out how fields revert to the cached
