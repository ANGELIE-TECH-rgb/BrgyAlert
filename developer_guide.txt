================================================================================
                    DEVELOPER SETUP & DEPLOYMENT GUIDE
                              BRGYALERT PLATFORM
================================================================================

This guide outlines step-by-step instructions for developers to install dependencies, 
configure environmental variables, deploy database instances, and execute local 
development servers for the BrgyAlert mobile-centric ecosystem.

--------------------------------------------------------------------------------
PART 1: GLOBAL SYSTEM PREREQUISITES
--------------------------------------------------------------------------------
Before setting up any component, ensure your machine has the following installed:

1.  Node.js: v18.x or v20.x (LTS Recommended) -> https://nodejs.org/
2.  Git: Version Control System -> https://git-scm.com/
3.  Firebase CLI: Global installer for Cloud deployments
    *   Command: `npm install -g firebase-tools`
4.  Expo Go (Mobile App): Download the "Expo Go" application on your physical iOS 
    or Android smartphone from the App Store or Google Play Store to run mobile builds.

--------------------------------------------------------------------------------
PART 2: BACKEND SETUP & CONFIGURATION (BrgyAlert_Backend)
--------------------------------------------------------------------------------
The backend is a Firebase serverless Backend-as-a-Service (BaaS) layout.

A. Local Firebase Authentication & Project Binding:
1.  Open your terminal and navigate to the backend folder:
    `cd BrgyAlert_Backend`
2.  Log in to your Google Account associated with the Firebase console:
    `firebase login`
3.  Retrieve your active project list to verify link:
    `firebase projects:list`
4.  Initialize project bindings (if deploying to a new console instance):
    `firebase use --add` (Select your target database project ID).

B. Understanding the Directory Structure:
*   `firestore.rules`: Security access rules. Run checks before modifying this file.
*   `firestore.indexes.json`: Composite search indexing definitions.
*   `firebase.json`: CLI project target settings.
*   `functions/`: Node.js cloud functions environment (SMS webhook handlers).

C. Deploying Database Configurations to the Cloud:
Run these commands from the `BrgyAlert_Backend` folder:
*   To deploy only security rules:
    `firebase deploy --only firestore:rules`
*   To deploy composite indexes (takes 5-10 minutes to compile in Firebase Console):
    `firebase deploy --only firestore:indexes`
*   To deploy SMS intake webhook functions:
    `cd functions && npm install`
    `cd .. && firebase deploy --only functions`

D. Setting up the Local Emulator Suite (For Sandbox Testing):
1.  Verify java SDK is installed on your computer.
2.  Execute the emulation stack locally:
    `firebase emulators:start`
3.  Open browser to `http://localhost:4000` to access the local database panel.

--------------------------------------------------------------------------------
PART 3: MOBILE APPLICATION DEVELOPMENT GUIDE (BrgyAlert_Mobile)
--------------------------------------------------------------------------------
The unified application is built on React Native using the Expo tooling layer, 
housing both the Citizen (User) and Administrator/Responder (Admin) interfaces.

A. Local Installation:
1.  Navigate to the mobile directory:
    `cd BrgyAlert_Mobile`
2.  Install dependencies:
    `npm install`
3.  Create environment configuration:
    *   Create a file named `src/services/firebaseConfig.js` (or edit the existing setup).
    *   Paste your Firebase SDK project keys here so the mobile app can sync with Firestore.

B. Executing the Application on Simulators or Physical Devices:
1.  Launch the Metro Bundler engine:
    `npm start` (or `npx expo start`)
2.  Choose your testing target:
    *   **Physical Device (Best option for GPS/Camera):** Scan the QR Code displayed 
        in your terminal with your mobile phone's camera (iOS) or the Expo Go 
        App QR Scanner (Android). Your phone must be connected to the same Wi-Fi 
        network as your computer.
    *   **Android Emulator:** Install Android Studio, open an Android Virtual 
        Device (AVD), and press `a` in your computer terminal to boot the build.
    *   **iOS Simulator:** Open Xcode (macOS only), open a simulator, and press 
        `i` in your terminal.

C. Testing the Smart SMS Offline Fallback:
1.  To simulate network disconnection on Android Emulator: Press `F8` or disable 
    Wi-Fi and mobile data in the emulator settings panel.
2.  To simulate on physical device: Turn on "Airplane Mode" with Wi-Fi disabled.
3.  Open the reporting form, enter mock details, and click "Submit".
4.  The application NetInfo sentinel will detect zero connectivity, intercept standard 
    Cloud sync, compress reports into a delimiter string (`BA!...`), and open 
    your phone's default text messaging app prefilled.

D. Compiling for Production (.APK for Android / .IPA for iOS):
We utilize Expo Application Services (EAS) for remote builds.
1.  Log in to your Expo account:
    `npx eas-login`
2.  Configure EAS parameters:
    `eas build:configure`
3.  Build a test APK package:
    `eas build --platform android --profile preview` (Outputs a downloadable APK 
    link for direct install on testing devices).

--------------------------------------------------------------------------------
PART 4: SEEDING DUMMY DATABASE REPORTS FOR TESTING
--------------------------------------------------------------------------------
To test priority queue lists, charts, and maps without manual submissions, seed the database:
1.  Log in to the mobile application using an Admin account.
2.  Navigate to the Admin Console's settings or Dev Utilities tab.
3.  Trigger the "Seeding tool" which fires a script to auto-generate 50+ incident 
    documents with randomized coordinates situated within your target Barangay boundaries.
4.  Navigate back to the Live Queue and stats screens to verify the generated charts 
    and urgent sorting lists immediately.
